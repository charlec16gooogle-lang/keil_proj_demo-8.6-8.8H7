### 二、 一些主要的命令意思
1. `git init`（初始化本地仓库）
2. `git add .`（文件加入暂存区）
3. `git commit`（提交版本到本地仓库）
4. `git checkout -b`（创建并切换新分支）
5. `git merge`（合并分支改动到主分支）
6. `git push`（同步推送代码到远程仓库）

### 三、“eggchan渲染”版的作业对应的具体操作和分步

#### 1. 第一次提交（+本地仓库初始化）
- **目标**：如何将一个普通文件夹变成受 Git 管理的版本控制仓库，并完成首个历史节点的记录。<mark>（实在还是不知道就到回去看B站之前的那个视频）</mark>
>[!NOTE]
>- **具体步骤与命令**：
 > 1. 打开作业工程根目录，在终端输入 `git init`
  >   - **命令含义**：在当前目录下生成隐藏的 `.git` 文件夹，正式开启 Git 版本追踪。
  >2. 输入 `git add .`
   >  - **命令含义**：将当前目录下的所有文件（自动排除 `.gitignore` 中指定的编译垃圾文件）添加到**暂存区（Staging Area）**。
    > -  --（统统来自于之前看的那个视频，操作手册目前还是没看懂...这个部分遇到还是不会的话，还是先看视频吧）
  >3. 输入 `git commit -m "first commit"`
   >  - **命令含义**：把暂存区里的文件快照正式提交到本地仓库，`-m` 后面跟着本次提交的说明文字。

#### 2. 代码修改与提交
- **目标**：当我们在项目开发中修改了部分代码后，如何只提交特定修改的文件。
>[!NOTE]
>- **具体步骤与命令**：
 > 1. 在左侧目录的资源管理器中 打开 `Core/Src/main.c`，将宏定义中的 `#define BLINK_TIMES 3U` 修改为 `5U` 并保存（`Ctrl + S`）。<mark>一定要保存啊</mark>
  >2. 输入 `git add Core/Src/main.c`
   >  - **命令含义**：只把被修改的 `main.c` 这一个文件加入暂存区。<mark>--易漏！</mark>
  >3. 输入 `git commit -m "将闪烁次数调整为5"`
    > - **命令含义**：生成一个新的提交节点，记录“闪烁次数改调为5”这一阶段性修改。<mark> --易漏！</mark>

#### 3. 创建并管理分支与代码合并
- **目标**：如何在开发验证的时候，不影响我们之前已经验证过的代码？--<mark>分支！</mark>在不影响主线（`main`）代码的情况下，我们在独立分支上开发新功能，验证无误后再合并回主线。
>[!NOTE]
>- **具体步骤与命令**：
 > 1. 输入 `git checkout -b feature-blink`
  >   - **命令含义**：`-b` 代表创建并直接切换到名字为 `feature-blink` 的新分支。
  >2. 在新分支下修改 `main.c` 中的闪烁/延时参数并保存。
  >3. 提交分支修改：
   >  - `git add Core/Src/main.c`
    > - `git commit -m "在feature-blink分支修改闪烁参数"`
  >4. 输入 `git checkout main`
   >  - **命令含义**：从开发分支切回主分支 `main`。
  >5. 输入 `git merge feature-blink`
   >  - **命令含义**：把 `feature-blink` 分支上做出的修改无缝合并进当前的 `main` 主分支。

#### 4. 体验版本回退
- **目标**：如何在写错代码或需要撤销操作时，将代码库回退到过去的某个历史状态。--如何实现在分支这些不同版本中，每一个版本的ctrl+z(reset)呢？
>[!NOTE]
>- **具体步骤与命令**：
 > 1. 输入 `git checkout -b practice-reset`：新建练习分支，防止在主分支上误删历史。
 > 2. 输入 `git log --oneline`
   >  - **命令含义**：以极简的一行格式查看历史提交记录及其对应的提交 ID。<mark>--（注意：是oneline不是online啊！）</mark>
 > 3. 输入 `git reset --hard HEAD~1`
   >  - **命令含义**：强制回退到上 1 个版本（`HEAD~1`），彻底抹掉最后一次提交中的所有改动。
  >4. 输入 `git checkout main`：练习完毕后无损切回主分支。

#### 5. 远程仓库同步
- **目标**：将本地的版本控制仓库上传到 GitHub 云端，实现代码云端备份与团队协作。
>[!NOTE]
>- **具体步骤与命令**：
  >1. 输入 `git remote -v`
   >  - **命令含义**：查看当前本地仓库绑定的远程仓库地址（`origin`）。
  >2. 输入 `git push -u origin main`
    > - **命令含义**：将本地的 `main` 主分支的所有提交记录推送到远程仓库 `origin`。
  >3. 输入 `git pull`
    > - **命令含义**：从远程仓库拉取最新的代码改动并与本地代码合并。
    > <mark>-- 嗯这里要注意的就是一定要确保自己网络很好 不行的话就只能多试几次...</mark>

### 四、 常用 Git 命令对照表

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `git status` | 查看当前工作区的修改状态与暂存状态 | 不确定文件是否有修改或提交时使用 |
| `git add .` | 将所有修改过的文件加入暂存区 | 代码保存后、准备生成提交节点前 |
| `git commit -m "说明"` | 将暂存区的改动正式提交到本地仓库 | 完成某项功能或阶段性修改后 |
| `git checkout -b <分支名>` | 创建并立刻切换到指定的独立分支 | 准备开发新功能或实验性修改时 |
| `git merge <分支名>` | 将指定分支的代码合并到当前分支 | 新功能开发测试完毕，准备合入主线时 |
| `git push -u origin main` | 将本地 `main` 分支推送到 GitHub 远程仓库 | 本地改动完成，需要上传备份或发布时 |

#### 2. 编译->烧录->文件名的作用
>[!NOTE]
>* **文件代表**：
 > * `.o` ：让CPU看懂的文件
 >* `.c` : 源文件，就是人编译的文件，
 >* `.axf` ：全局可执行的文件，已经有专门的内存地址之类的
 >* `.hex` ：从 `.axf` 提炼出的烧录机器码，最终的烧录文件，将程序写入控制器和存储器。
>* **F7的编译+F8的下载 的本质**:
  >F7进行的是首先编译+汇编--.c文件翻译为.o文件，然后是链接--通过给.o文件分FLASH和RAM的内存地址，合成.axf，提取.hex。然后F8负责下载到板子上，把代码>告诉板子。
>* **编译与下载**：
  >* **F7 (Build)**：增量编译。仅重新编译被修改过的 C 文件及其受影响的模块，然后重新链接生成 `.axf`/`.hex`。
  >* **Rebuild**：重新全编译。清除所有历史 `.o`/`.axf` 文件，对整个工程所有文件重新编译。(这两个概念的解释来自于AI)
  >* **关系**：修改 C 代码只是改变了文本文件，必须按下 **F7** 重新生成芯片能识别的机器码，再按 **F8** 下载才能在单片机上呈现新现象。
  >         <mark>--所以我们rebuild重新编译了以后需要重新F7+F8.</mark>

#### 3. keil5的配置：文件的添加和删除
对比<mark>删除 Include Paths </mark>与<mark>删除 Group 文件</mark>，找到.h.c等文件之间的关系
>[!NOTE]
>* **实验 1：移除 Include Paths 里的 `..\hardware\inc`**
 > * **结果**：F7 编译产生 4 个 errors，像`error: 'buzzer.h' file not found`、`error: 'led.h' file not found`。
 >* **原因**：`#include` 负责请求复制头文件内容，而 `Include Paths` 是编译器的<mark>导航地图</mark>。删去路径后，编译器在处理 `#include "buzzer.h"` 时找不到该头文件，所以会报错。
>* **实验 2：移除 Group 里的 `buzzer.c` 与 `led.c`**
  >* **结果**：F7 编译报 5 个 errors，像 `Error: L6218E: Undefined symbol buzzer_init (referred from main.o)`。
  >* **原因**：Include Paths 没问题，头文件声明存在，`main.c` 能正常编译生成 `main.o`；但因 `.c` 源文件被我们删掉了，未加入 Group 参与编译，链接器在组合所有 `.o` 时<mark>找不到函数的具体实现代码</mark>，所以会报错。
>* **总结**：
  >* **Include Paths (`.h`)**：相当于<mark>道路</mark>，告诉编译器有哪些函数和变量在哪里。缺了显示 `file not found`。
  >* **Group (`.c`)**：<mark>提供具体函数体</mark>，就是代码中每一个函数的方程内容，缺了显示 `Undefined symbol`。
